# 데이터 인벤토리: 가상 데이터와 실제 데이터

시나리오: 차주 6곳이 건물 신축·증축 시설자금을 신청하고, 시공사 6곳이 책임준공을 확약하는 구조입니다 (README의 사례표 참고).

## A. 가상 데이터 (직접 만든 것)

실제로는 차주가 제출하거나 은행 내부 시스템에 있는 자료입니다. 외부에서 받아올 방법이 없어 PoC용으로 만들었습니다. `data/cases/generate.py`로 다시 만들 수 있습니다.

### A-1. 차주 제출서류 (`cases/C1~C6/`, 사례마다 5종)

| ID | 문서 | 필수 | Agent가 확인하는 것 |
|---|---|---|---|
| SUB-01 | 여신거래신청서 | 필수 | 신청금액, 기간, 상환방식, 신청금리, 시공사 |
| SUB-02 | 사업계획서 | 필수 | 총사업비, 자금조달, 추가 현금흐름(임대·비용절감) |
| SUB-03 | 공사도급계약서(책임준공 포함) | 필수 | 도급액, 계약금액 조정 조항, 확약서 원본 여부, 배상한도 |
| SUB-04 | 감정평가서 | 필수 | 토지가치, 준공 후 가치 → LTV |
| SUB-05 | 재무제표 | 선택 | DART 미연결 시 대체 자료 |

### A-2. 은행 내부자료 (`bank/`)

| ID | 자료 | 민감도 |
|---|---|---|
| REG-01~03 | 여신업무규정, 시설자금 취급세칙, 건설여신 심사가이드 | 사내 |
| INT-01 | 차주 거래현황 (`borrowers.json`) | internal |
| INT-02 | 내부신용등급 (`borrowers.json`) | **restricted** (RM 열람 불가) |
| INT-03 | 시공사 책임준공 약정 관리현황 (`contractors.json`) | internal |
| POL-01 | Agent 권한정책 (`권한정책.json`) | - |

시공사 행정처분 이력 중 GS건설(2023 검단)과 HDC현대산업개발(2022 광주 화정)은 공개 보도된 사건이며, 그 외 약정 한도·등급 등은 가상입니다.

## B. 실제 데이터 (API로 받아올 수 있는 것)

| 데이터 | 출처 | 인증 | PoC 연결 |
|---|---|---|---|
| 기준금리, CD91, 국고채3년, 대기업대출금리 | 한국은행 ECOS | 인증키 (`sample` 키로 10건까지) | **구현** |
| 외부뉴스 | Google News RSS | 불필요 | **구현** |
| 재무제표·기업개황·공시 | OpenDART | 무료 인증키 (사용 IP 등록) | **구현** |

| 실거래가·공시지가 | 국토부 공공데이터 | 인증키 | 미구현 |
| 시공능력평가·행정처분 | 대한건설협회, KISCON | 기관별 | 미구현 |
| 외부 신용등급·CB | NICE, KIS 등 | 유료 계약 | 해당 없음 |

## C. Fallback 순서

1. **실시간 API** 호출
2. 실패하면 **로컬 캐시**(`data/cache/`, 마지막 성공 응답)를 쓰고 보고서에 "캐시 사용"으로 표시
3. 캐시도 없으면 **대체 자료**(예: DART → 차주 제출 재무제표)를 쓰고 심사역 확인 항목에 자동 추가
4. 대체 자료도 없으면 "확인 불가"로 두고 사람에게 넘김 (Agent가 값을 추정하지 않음)
